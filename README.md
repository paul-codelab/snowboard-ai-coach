# snowboard-ai-coach — 單板滑雪動作影片分析（snowcoach）

> ⚠️ **非專業建議，僅供參考。** 本工具由電腦自動分析影片，並非專業教練的評估，數值與建議可能有誤。練習時請量力而為、注意安全並配戴護具；如需正式指導，請洽合格的單板教練。

把一段單板滑雪影片變成：**疊上骨架與數值的影片（中文字幕）**、**每格數據 CSV**，以及一份**中文摘要報告與一個最優先的建議**。

支援自拍桿（Insta360 X 系列隱形自拍桿、GoPro）與他人拍攝（跟拍、定點、手機）。只用 CPU 就能跑。

疊圖影片左上角的面板：每個指標的數值、綠色目標區間與目前位置（綠 = 在區間內、黃 = 偏離、紅 = 明顯偏離、灰 = 無法判斷），下方是最近 3 秒的立刃軌跡（藍色 = 腳尖側、橘色 = 腳跟側，和 HTML 報告一致）。板子軸線由雙腳推算，顏色表示目前用哪一邊的刃。

本專案以 **AGPL-3.0** 開源，另提供商業授權，見[授權](#授權)。

## 不會用電腦指令？雙擊就能用（Mac／Windows）

不需要事先安裝任何東西。

1. **下載**：在 GitHub 頁面按綠色的 **Code** → **Download ZIP**，然後解壓縮。
2. **雙擊**資料夾裡的啟動檔：
   - **Mac**：`start-mac.command`
   - **Windows**：`start-windows.bat`
3. **第一次**會自動安裝（約 5～10 分鐘，需要網路），完成後瀏覽器會自動打開分析頁面。
4. **之後**只要再雙擊同一個檔案，幾秒鐘就會打開。用完把那個黑色（或白色）的視窗關掉即可。

**第一次打開時的安全提示**（工具沒有付費簽章，系統會先擋一下）
- **Mac** 出現「無法打開，因為它來自未識別的開發者」：在檔案上**按右鍵（或 Control＋點按）→ 打開 → 打開**。只有第一次需要這樣做。
  如果還是打不開：「系統設定 → 隱私權與安全性」，在下方找到 start-mac.command，按「強制打開」。
- **Windows** 出現「Windows 已保護您的電腦」：按 **其他資訊 → 仍要執行**。

**說明**
- 安裝完成後可以**完全離線使用**，影片只在你自己的電腦上分析，不會上傳到任何地方。
- 所有東西都裝在這個資料夾裡（`.venv`、`models`），**刪掉資料夾就等於解除安裝**。分析結果在資料夾裡的 `out/gui`。
- 更新：下載新版 ZIP、解壓縮後雙擊即可，有需要時會自動重新安裝。
- 安裝失敗時，視窗會顯示錯誤訊息，請截圖到 [Issues](../../issues) 回報。

## 安裝

需要 Python 3.10 以上。

```bash
pip install -e .                # 基本功能（MediaPipe，Apache-2.0）
pip install -e ".[h264]"        # 建議：輸出 H.264 影片，手機/瀏覽器可直接播放
pip install -e ".[gui]"         # 圖形介面（本機網頁）
pip install -e ".[yolo]"        # 選用：YOLO11 偵測器/姿勢後端（AGPL-3.0，見下方授權說明）
pip install -e ".[dev]"         # 開發：pytest
```

Linux 伺服器（沒有桌面環境）另外需要 MediaPipe 用到的系統函式庫：

```bash
sudo apt-get install -y libegl1 libgles2
```

第一次執行會自動下載模型到 `~/.cache/snowcoach`（可用環境變數 `SNOWCOACH_MODELS` 改位置）。

影片中文字需要中文字型：Windows / macOS 內建即可；Linux 請安裝 `fonts-noto-cjk` 或 `fonts-wqy-zenhei`，或用 `SNOWCOACH_FONT=/path/to/font.ttc` 指定。

## 快速開始

```bash
# 自拍影片（自動判斷拍攝方式與站姿）
snowcoach analyze "my_run.mp4" --level 中級

# 已知站姿、只分析第 10~25 秒
snowcoach analyze my_run.mp4 --stance goofy --start 10 --end 25 --level beginner

# 朋友跟拍、騎手在畫面中很小：改用 YOLO 找人
snowcoach analyze friend.mp4 --source follow --detector yolo --level advanced

# GoPro 超廣角
snowcoach analyze gopro.mp4 --lens gopro-wide
```

也可以用 `python -m snowcoach analyze ...`。結果預設寫到 `out/<影片檔名>/`。

repo 不附影片（避免著作權問題），請用自己的影片。

## 圖形介面（不用打指令）

```bash
pip install -e ".[gui]"
snowcoach gui
```

瀏覽器會自動打開介面：

1. 把影片拖進左上角的框。
2. 選**程度**；知道慣用站姿的話直接選 Regular 或 Goofy，會比自動判斷準。
3. 按 **開始分析**，右邊會顯示進度。
4. 完成後右邊會出現：疊圖影片、**最優先的建議**與完整報告，以及可以下載的 `report.html`（用瀏覽器打開，圖表可以點看數值）和全部結果的 zip。

「進階設定」裡可以調整 switch 偵測、相機側傾、鏡頭校正、找人用的偵測器、只分析某一段（開始/結束秒數），以及關掉疊圖影片來加快速度。

- 分析在你自己的電腦上進行，**影片不會上傳到網路**。結果也存在 `out/gui/` 資料夾。
- 預設只有這台電腦能開啟介面。想用手機操作（手機和電腦在同一個 Wi-Fi）：`snowcoach gui --lan`，再用手機瀏覽器打開終端機顯示的電腦 IP，例如 `http://192.168.1.23:7860`。同一個網路裡的其他人也能連進來，在公共 Wi-Fi 上請不要使用。
- 其他選項：`--port 8000` 改埠號、`--no-browser` 不自動開瀏覽器。

## 在 GitHub 上試跑（不用在自己電腦安裝）

### 方式一：Actions，按按鈕分析 repo 裡的影片

1. 先 fork 這個 repo，把影片上傳到**你自己的 repo**（例如放在 `samples/` 資料夾；網頁上傳單檔上限 25MB）。⚠️ 公開 repo 裡的影片任何人都看得到；不想公開請改用下方的 Codespaces 或在自己電腦上用。
2. 到 repo 的 **Actions** 分頁 → 左側選 **分析影片** → 右側 **Run workflow**。
3. 填入影片路徑（例如 `samples/my_run.mp4`），選程度、站姿等，按綠色的 **Run workflow**。
4. 約 3～6 分鐘後點進該次執行：頁面上會直接顯示中文摘要；下方 **Artifacts** 可以下載結果 zip（`report.html`、疊圖影片、CSV）。

「分析影片」要在 `main` 分支上才會出現在 Actions 分頁。私人 repo 的免費帳號每月有 2000 分鐘，分析一支影片大約用 5 分鐘。

另外，每次推送或開 PR 時，**測試** workflow 會自動跑全部測試，PR 頁面會顯示結果。

### 方式二：Codespaces，在雲端開圖形介面

1. 在 repo 頁面按綠色的 **Code** → **Codespaces** 分頁 → **Create codespace on main**。
2. 第一次開啟會自動安裝環境（約 3～5 分鐘），完成後會自動啟動圖形介面，並在瀏覽器開新分頁。沒有自動開的話，到下方的 **連接埠（Ports）** 分頁點 7860 旁的地球圖示。
3. 接下來和本機的圖形介面操作一樣：拖放影片、選項、開始分析。

個人帳號每月有免費額度（2 核心機器約 60 小時）。**用完請停止 codespace**（repo 頁面 Code → Codespaces → ⋯ → Stop），否則會繼續計時；預設閒置 30 分鐘會自動停止。

## 參數

| 參數 | 值 | 說明 |
|---|---|---|
| `--source` | `auto`（預設）/ `selfie` / `follow` | 拍攝方式。自拍時，持桿手會帶動肩膀，肩膀對齊只顯示不評分 |
| `--stance` | `auto`（預設）/ `regular` / `goofy` | 慣用站姿。regular = 左腳在前。建議直接指定 |
| `--no-switch` | | 不偵測 switch（逆腳）滑行，整段都用慣用站姿計算 |
| `--roll` | 度數，例如 `-8` | 相機側傾修正：畫面中水平線「右低左高」為正。相機明顯歪斜時使用 |
| `--level` | `beginner` / `intermediate`（預設）/ `advanced`，或 `初學` / `中級` / `進階` | 決定目標區間，見下方 |
| `--lens` | `none`（預設）/ `gopro-wide` / `gopro-superview` / `fisheye:<對角視角>` / `calib:<json>` | 鏡頭變形校正，見下方 |
| `--backend` | `mediapipe`（預設）/ `yolo-pose` / `sam3d` | 姿勢模型。`sam3d` 目前只保留介面 |
| `--detector` | `mediapipe`（預設）/ `yolo` / `none` | 追蹤遺失時找人用的偵測器 |
| `--model` | `lite` / `full`（預設）/ `heavy` | MediaPipe 模型大小 |
| `--start` / `--end` | 秒 | 只分析一段 |
| `--stride` | 整數 | 每 N 格分析一格，加快速度 |
| `--no-video` | | 不產生疊圖影片 |

### 程度

| 程度 | 定義 |
|---|---|
| 初學 `beginner` | 能用落葉飄或滑行式（會側滑）轉彎下緩坡，正在練習連續換刃。 |
| 中級 `intermediate` | 能在中級道連續轉彎、換刃順暢，開始用立刃減少側滑。 |
| 進階 `advanced` | 能在各種雪道刻滑（carving），轉彎時板刃切雪，身體有明顯的傾倒與折髖。 |

同一個數值對初學者是問題、對進階者可能是正確技術（例如大幅傾倒），所以目標區間依程度不同。區間定義在 [`snowcoach/coach/targets.py`](snowcoach/coach/targets.py)，可以自行調整。

## 輸出

| 檔案 | 內容 |
|---|---|
| `overlay.mp4` | 骨架、板子軸線、指標面板、立刃軌跡、中文字幕建議 |
| `metrics.csv` | 每格一列：立刃狀態、轉彎編號、各指標數值；**數值為空時 `*_note` 欄寫明原因**（例如「左膝未入鏡」）。UTF-8 BOM，Excel 可直接開 |
| `keypoints.csv` | 每格每個關節的像素座標與信心值 |
| `report.html` | **建議先看這個**：單一檔案、不需網路，手機也好讀，可以直接傳給朋友。含最優先建議與「問題最明顯的畫面」、各指標狀態、隨時間變化的圖表（標出轉彎與目標區間，可點看數值）、每個轉彎的代表畫面 |
| `report.md` | 中文摘要報告：拍攝資訊、**一個最優先的建議＋練習方法**、各指標統計、每個轉彎的數據、限制說明 |
| `summary.json` | 報告的機器可讀版本 |

### 指標

所有指標都在「由雙腳推算的板子座標系」中計算，與相機位置無關。

| 指標 | 定義 | 需要看得到 |
|---|---|---|
| 膝蓋彎曲（前膝/後膝） | 髖–膝–踝夾角換算成彎曲度，0° = 打直 | 該側的髖、膝、踝 |
| 身體傾倒 | 重心偏離鉛直線的角度，分腳尖側/腳跟側 | 雙腳、雙髖、雙肩 |
| 折髖 | 下半身傾倒減上半身傾倒；正 = 有折髖，負 = 整個人往內倒（只在轉彎中評） | 同上 |
| 前後重心 | 重心沿板子方向的位置（以站距為單位，+ 偏板頭） | 同上＋站姿 |
| 肩膀對齊 | 肩線與板子的夾角（水平面），+ = 開肩 | 同上＋站姿 |
| 前腳負重（左右腳負重） | 由前後重心換算的前腳負重比例；搭配「兩膝差」看兩腳是否平均出力 | 同上＋站姿 |

轉彎以「身體傾倒的正負號改變」切分（重心每次換刃都會越過板子），每個轉彎標示腳尖側或腳跟側。

### 建議怎麼挑

依單板教學的因果順序 **平衡 → 壓力 → 立刃 → 旋轉**，只給排在最前面、且確實有問題的那一項（例如重心在後座時，也常會跟著出現肩膀旋轉；先改重心，肩膀常會自己變好）。

- 報告：某指標在可判斷的資料中 ≥ 40% 超出目標區間，或 ≥ 15% 明顯超出，才算問題；資料不足（少於 1 秒，或少於 2 個轉彎）的指標不下結論，並在報告中列出。
- 影片字幕：同一時間只有一句；明顯偏離（紅色）或偏離持續 1.5 秒才出現；至少持續 0.6 秒才顯示；講 3 秒就休息 1.5 秒。

## 看不到就不猜

- 關節不在畫面內 → 「○○未入鏡」；在畫面內但模型信心低 → 「○○被遮擋或看不清」。
- 姿勢估計超出人體可能範圍（例如傾角 > 75°、兩腳距離與腿長不符）→ 「姿勢估計不合理」。
- 騎手在畫面中不到 160 像素高 → 「騎手在畫面中太小」。
- 單格突然跳動的數值 → 「數值突然跳動，視為偵測誤差」。
- 缺值不會被內插或補值；報告只用有數值的影格計算。

## 站姿與 switch

單板可以 switch（逆腳）滑行，同一段影片裡前腳可能換邊。所以工具分成兩件事：

- **慣用站姿**（regular/goofy）：`--stance` 指定；沒指定時取影片中佔多數的方向（需 3 秒以上、70% 一致）。
- **每一段的前腳**：每格依「頭部朝向」與「胸口朝向」（肩膀往板頭打開）投票，前後 1 秒平均，同一方向持續 2 秒以上才成立；與慣用站姿相反的段落標為 switch，前後腳對調計算。換邊的過渡、證據不足的片段標示「滑行方向不確定」，不猜。

雙手位置也試過，但在測試影片上會投反（自拍時唯一可用的手是後手，常伸向板尾），所以不採用。

慣用站姿無法確定時，前後重心與肩膀對齊只顯示數值、不給建議（方向判斷錯會讓建議完全相反）。

## 自拍 vs 他人拍攝

自動判斷依據三個特徵：騎手在畫面中的大小、大小是否穩定、是否有一隻手伸向鏡頭（持桿手）。判斷結果和信心寫在報告中；不確定時以他人拍攝處理並提示用 `--source` 指定。

騎手在畫面中太小時（例如跟拍滑遠後），指標會改為「無法判斷」，不會亂猜。

## 鏡頭校正

| 相機 | 建議 |
|---|---|
| Insta360 X 系列（App/Studio 重新構圖後輸出） | `none`（預設）。重新構圖輸出不是固定的魚眼投影，沒有通用參數；建議開水平鎖定 |
| 手機 | `none` |
| GoPro 超廣角 / SuperView | `gopro-wide` / `gopro-superview`（等距魚眼近似）；Linear 模式用 `none` |
| 其他魚眼 | `fisheye:<對角視角度數>`，或用 OpenCV 校正後 `calib:cam.json` |

`calib` 檔格式：`{"model": "fisheye" 或 "pinhole", "K": [[fx,0,cx],[0,fy,cy],[0,0,1]], "D": [...], "size": [寬, 高]}`。

## 拍攝建議（讓更多指標能判斷）

- 全身入鏡，**包含雙腳與板子**；腳看不到時，傾倒、折髖、前後重心都無法判斷。
- 騎手在畫面中至少約 1/8 高（1080p 直式約 250 像素以上）。
- 相機保持水平（Insta360 開水平鎖定）；傾倒是以畫面垂直方向當作重力方向。相機明顯歪斜時用 `--roll` 修正。
- 慣用站姿請直接用 `--stance` 指定最可靠；switch 片段會自動偵測。

## 限制

- 3D 姿勢由單一鏡頭影像推估（MediaPipe），角度是近似值，適合看趨勢、自己前後比較，不宜當成精確量測。深度刻滑、騎手很小、動作很快時容易失準（這些影格會盡量標成無法判斷，但不保證全部抓到）。
- 相機明顯傾斜（跟拍時常見）會讓傾倒角度偏差。工具不會自動從畫面偵測地平線來校正：滑雪場畫面中天空與雪的交界多半是**斜坡的邊緣**而不是真正的地平線，自動校正反而容易校錯，所以改用 `--roll` 手動指定。
- 剪輯過的影片（子母畫面、換場）可能短暫追蹤到畫面中的其他人。
- 目標區間是依一般教學原則訂的起始值，不是量測標準。

```bash
pytest -m "not slow"   # 只跑快速的單元測試
```

單元測試用「已知答案的合成 3D 骨架」加上隨機相機旋轉，驗證每個指標的數值與正負號，以及看不到時回傳的原因。把自己的滑雪影片（`.mp4`）放在 repo 根目錄，`pytest` 也會用它跑一次真實影片的整合測試（影片已被 `.gitignore` 排除，不會被提交）。
